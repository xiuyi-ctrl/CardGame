# 驯牌远征（PetCard Rogue）

一款以驯服、融合与队伍构筑为核心的回合制肉鸽卡牌宠物对战游戏。选择初始伙伴，穿越三幕随机地图，驯服残血敌人、融合相同物种成长，并在首领战中完成远征。

- **版本**：0.4.1
- **技术栈**：Electron + Vite + React 18 + TypeScript
- **平台**：Windows 便携版 `.exe`
- **核心特性**：固定数值回合战斗、可复现随机、残血驯服、融合进化、专属被动、随机地图与事件、熟练度远征

标题页采用独立的夜色营地像素背景与「叠放卡牌—山林道路—爪印」横向徽记；标题和按钮为真实界面文字，不嵌在背景图片中。继续游戏有可用存档时为主按钮，否则突出新游戏；存档管理、生物图鉴、成就与测试入口仍保留。

标题页仅大标题使用随游戏离线打包的 [Fusion Pixel Font](https://github.com/TakWolf/fusion-pixel-font) 简体中文像素字形（SIL OFL 1.1）；副标题、按钮及正文使用系统字体。授权与上游说明见 `src/ui/fonts/fusion-pixel/`。

开局选择界面使用三张独立背景：主线第一步的林间契约祭坛、第二步的石廊，以及熟练度远征的室内试炼大厅，不复用营地背景。主线先从迅迅／泡泡／灼灼中选一只主力（获得同种 2 只），再从铁墩／咪咪／刺刺中选一只同伴；选择卡片后按金色按钮确认。熟练度远征从六只基础生物中任选两只，按选中顺序出发。卡片中的生物、生命与速度从游戏数据实时绘制，主线技能名称可悬停查看；早期构图预览见 [主线第一步](design/previews/starter-main-step1-v2.png)、[主线第二步](design/previews/starter-main-step2-v2.png) 与 [熟练度远征](design/previews/starter-proficiency-v2.png)。

主线两步的生物卡共用独立的苔石龛位素材：立绘置于石质站台上，名称与生命／速度嵌入同一块下方铭牌，选中时整座石龛显出青绿光晕；熟练度六选二仍使用紧凑卡片。石龛只含美术底图，宠物及文字仍由界面实时叠加。

当前使用的生物、背景、底座和徽记图像统一备份在 [美术素材](美术素材/README.md) 文件夹；游戏仍从 `public/` 与 `src/ui/assets/` 加载对应文件，以兼容已有存档中的图片路径。

地图界面采用像素冒险地形：主线三幕依次使用森林、暗影沼泽和余烬险地背景，熟练度远征使用古塔山路背景。节点以不规则石质底座、彩色像素图标和独立铭牌呈现，当前节点带青绿光晕；文字与路线独立于背景绘制。路线只连接地图数据中相邻且可通行的上下两层，金色表示已走路径，青绿表示下一步可达，虚线表示悬停或键盘聚焦后的后续预览。侧边信息只展示已知的节点类型与风险，具体敌人、货物和奖励仍须侦查；窄窗口中信息区移至地图下方。

战斗界面采用左侧像素战场、右侧操作栏布局。战场使用紫色地面背景，生物图像统一以低分辨率像素采样呈现；迅迅使用独立像素立绘。每只生物站在草石底座上，底座下方依次用闪电和心形图标、奶白色黑描边像素数字动态显示速度和生命。四行阵列按战场实际高度缩放，无需滚动即可完整显示。右侧上方显示战斗记录，下方显示选中生物详情、技能和战斗操作，结束回合始终位于操作栏底部。

战前布阵界面使用独立的夜色营地背景，背景完整铺入左侧战场、不裁掉帐篷顶和底部地形（超宽窗口会按战场比例拉伸）。顶部为战前标题、当前地点与敌方生物头像、出战数量和返回地图，不显示推荐战力；六个站位在水平和垂直方向向中间聚拢，前后排使用青绿描边的深色铭牌。生物使用独立草石底座，空位使用青绿符文底座，均由界面实时放置而非烘焙在背景里。悬停或键盘聚焦已上场生物时，定位光圈显示在对应底座表面。右侧石框内为两列待命伙伴、不可点击的空队伍位、当前聚焦生物资料卡和金色确认出战按钮。未操作时默认预览第一只待命生物；普通布阵支持点击候选宠物按 从左到右、从上到下 顺序自动上阵、点击场上宠物下阵，并保留拖拽自由换位，模拟战显示只读的全员总览。视觉构图参考见 [桌面预览](design/previews/formation-1280x860.png) 与 [紧凑预览](design/previews/formation-960x640.png)；预览中的宠物与数值仅为示意。

战后休整界面使用独立的夜色营地背景，左侧以八格肖像展示存活伙伴，右侧显示选中伙伴的真实生命、速度、被动、技能及可用的融合、释放、净化操作；底部可继续前进。点击伙伴只切换查看对象，不改变出战阵容；普通队伍管理和满员处理新伙伴界面保持原有流程。视觉参考见 [战后休整预览](design/previews/roster-1280x860.png)，其中数值与队伍仅为示意。

战后奖励界面采用像素森林营地与战利品箱场景，右侧石框按实际奖励显示两项或三项可领取选项。金币、食物、治疗与招募分别展示对应图像、名称和效果；悬停或键盘聚焦时以青绿描边提示，点击即领取并进入战后休整。跳关获得奖励时标题显示「跳关奖励」。视觉参考见[战后奖励预览](design/previews/reward-main-pixel-v2.png)；场景和交互文字分层绘制。

主线与熟练度商店共用林间流动商棚背景：顶部展示地点、金币、出战数量与离开入口；右侧货架按两列展示四件实际商品，以像素图标区分物品，并明确显示可购买、已购买和金币不足状态。主线货架下方保留免费休整与刷新，熟练度只显示刷新；商品名称、说明与按钮均使用系统字体，价格按当前难度的实际扣款显示。视觉参考见 [主线预览](design/previews/shop-main-1280x860.png)、[熟练度预览](design/previews/shop-proficiency-1280x860.png) 与 [紧凑预览](design/previews/shop-main-960x640.png)。

## 游戏特色

### 主线远征

- 三幕随机地图：第 1/2/3 幕分别约 8～10、10～12、12～14 层，路线包含战斗、精英、事件、商店、休憩、奇遇、竞技场等节点。
- 队伍上限 8 只、最多出战 5 只；敌人生命低于 40% 时可用食物驯服。宠物战败会永久离队，战斗胜利后全队恢复生命。
- 宠物仅有生命与速度两项基础属性。伤害由技能固定数值与被动、状态、道具等固定修正组成，没有随机浮动。
- 相同物种可融合进化：第 n 阶形态需要 n+1 只同物种作为材料。奇遇还能提供属性强化、自创宠物、诅咒与超进化等选择。
- 每只生物都有专属被动，例如减伤、反伤、吸血、灼烧、中毒、速度成长、召唤与首领机制。
- 三档难度同时调整敌方生命、速度、商店价格与续航；幕间提供最低生命保护，避免多个惩罚轴叠加成断崖。
- 斗兽场对手生命降至 85% 且最多高出战宠物一阶；车轮战前两幕固定两轮、第三幕概率三轮，每轮胜利恢复 20% 生命。

### 战斗系统

- 每回合先为我方宠物下达技能、休息或换位指令；结束回合后，双方按速度与先手优先级统一结算。
- 支持护盾、灼烧、中毒、眩晕、降攻、减速、恐惧、技能封印、冷却与单场使用次数。
- 战斗日志保存生命、护盾与状态快照；界面按事件顺序回放攻击、治疗、多段伤害、范围伤害、召唤与状态动画。
- 全部随机通过种子和随机调用计数控制，同一初始状态可稳定复现战斗、地图、事件与奖励结果。

### 熟练度远征

通关主模式第 1 幕后解锁的独立 50 层爬塔模式。

- 从 6 只初始宠物中选择 2 只开局，不能在战斗中驯服或进行普通融合。
- 战斗获得成长点，可提升生命、速度、技能槽与技能强度，也可转移成长点或重置强化。
- 第 15、30 层出现随机 Boss，第 50 层挑战成长之主。
- 敌人生命按三段曲线成长，速度每 10 层固定 +1；16 层后精英单位才获得额外技能强化。
- 第 14、29 层固定为 Boss 前休整；第 15 层 Boss 最多携带 1 只小怪。
- 包含铁匠铺、三种竞技场模式、成长商店、专属事件、复活和休憩融合等内容。

## 快速开始

### 环境要求

- Node.js 20 或更高版本
- npm 10 或更高版本
- Windows（开发与打包目标平台）

### 安装依赖

国内网络环境可使用 Electron 镜像：

```powershell
$env:ELECTRON_MIRROR = 'https://npmmirror.com/mirrors/electron/'
npm install
```

其他环境直接执行：

```bash
npm install
```

### 开发、验证与打包

```bash
# 启动 Vite 与 Electron，支持热更新
npm run dev

# 运行单元测试与整局模拟
npm test

# 运行统一数值平衡模拟（主线三难度 + 熟练度，各 100 种子）
npm run balance

# 对固定基线执行流程稳定性、确定性和数值差异检查
npm run balance:check

# TypeScript 类型检查
npm run typecheck

# 构建渲染进程和 Electron 主进程
npm run build

# 打包 Windows 便携版，产物位于 release/
npm run dist
```

当前测试基线为 **33 个测试文件、412 项测试**，覆盖战斗、多段攻击、Boss、地图连通性与界面路线、战斗动画、开局选择、战前布阵、商店与战后休整、存档迁移、熟练度成长、统一平衡报表与 100 种子整局自动模拟。

平衡工具将 JSON 原始数据和 Markdown 汇总写入 `balance-output/latest/`。技能指标按模式、难度和阵营拆分，并记录技能解析目标数。`npm run balance:deep` 将每个配置扩展到 1000 个种子；只有确认新数值可作为后续参照时，才运行 `npm run balance:baseline` 更新受版本控制的基线。完整指标与参数见[数值平衡工具](游戏文件/数值平衡工具.md)。

若本地打包遇到 winCodeSign 符号链接权限错误，可在 PowerShell 中先执行：

```powershell
$env:CSC_IDENTITY_AUTO_DISCOVERY = 'false'
npm run dist
```

## 项目结构

```text
src/
├─ game/                         # 与 UI 解耦的纯游戏逻辑
│  ├─ core/
│  │  ├─ battle.ts               # 战斗创建、指令、结算、AI、状态与被动
│  │  ├─ growth.ts               # 熟练度成长、技能强化与成长点转移
│  │  ├─ growth-map.ts           # 50 层远征地图与敌人生成
│  │  └─ enemy-progression.ts    # 远征敌人的技能替换与强化
│  ├─ data/                      # 生物、技能、被动、食物、道具与模式数据表
│  ├─ state/
│  │  ├─ game.ts                 # 地图、事件、奖励、融合、难度、遗物与统计
│  │  └─ reducer.ts              # 全局状态机与全部游戏动作
│  ├─ rng.ts                     # 可播种随机数
│  ├─ simulation/                # 自动玩家、平衡指标、基线比较与 CLI 参数
│  └─ types.ts                   # 核心领域类型
├─ ui/                           # React 界面、战斗动画和本地存档
└─ electron/                     # Electron 主进程与预加载桥接

tests/                           # Vitest 单元、流程和模拟测试
游戏文件/                         # 玩法、敌人、Boss、关卡与数值设计文档
public/                           # 游戏图片资源
```

## 存档与数据

- 提供 6 个存档槽位；每个槽位可同时保存主线远征与熟练度远征。
- Electron 环境下存档写入应用数据目录；浏览器调试环境下自动回退到 `localStorage`。
- 难度、遗物、最高评级及熟练度模式解锁均按存档槽位独立保存；在同一槽位开始新游戏或重开熟练度远征会保留这些成就，只有删除整个槽位才会清空。
- 存档格式带有显式版本号；当前为 `saveVersion: 1`。加载时会自动迁移旧版单模式存档和无版本号双模式存档，并拒绝损坏或高于当前程序版本的存档。

## 开发约定

- 游戏逻辑中的随机行为必须通过 `createRng` / `useRng` 管理，确保可复现与可测试。
- 修改游戏规则时，应同步补充或更新对应的 Vitest 测试。
- 修改代码后需同步更新受影响的 README 与 `游戏文件/` 设计文档。
- 未经明确需求，不启动浏览器自动化；常规验证使用测试、类型检查和构建即可。

## 发布

推送形如 `vX.Y.Z` 的标签会触发 GitHub Actions：在 Windows 环境执行依赖安装、构建和便携版打包，并创建 Release 上传 `.exe`。

发布前请确保标签版本与 `package.json` 中的版本一致：

```bash
git push origin main
git tag v0.4.1
git push origin v0.4.1
```

产物命名为 `驯牌远征-<version>.exe`。
