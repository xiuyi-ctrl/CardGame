## 手机操作

- 请求左右横屏，使用动态视口并预留安全区。系统不接受横屏时显示提示，可以选择暂时继续当前方向；竖屏仅作基础兜底，不承诺与横屏相同体验。
- 战斗四行战场与右侧操作栏分离，技能区域单独滚动，结束回合固定；日志从顶部入口展开。
- 每只生物有详情点击入口；手机我方详情包含技能和 Buff，电脑右键仍只查看原有 Buff 信息。
- 取消目标无需 Esc；右键、键盘与拖拽的电脑操作保留。
- 布阵点击“调整站位”，默认取当前预览伙伴，再点击目标格；目标已有伙伴时沿用交换规则。调整模式中点击候选可更换待放置伙伴，取消不会下达战斗指令。
- 车轮战点击前移/后移调整顺序，点击伙伴移回候选的原操作保留。
- 图鉴、背包手机端先显示列表，点击后显示详情，提供返回目录/列表。
- 允许内容区手指滚动；不因隐藏滚动条而裁掉内容。按钮原则上至少44px高，实际小屏触点与遮挡仍须真机复查。

## 返回键与恢复

Android 返回键优先关闭可关闭弹窗、导入确认或详情，然后取消目标/站位选择；布阵、车轮战和背包按原返回动作处理。不能绕过胜负结算、招募锁定等强制步骤；无法直接返回时打开菜单。菜单可返回首页，首页退出需确认。

手机切后台立即尝试保存最新逻辑状态，动画计时保留剩余时长，恢复后继续显示，不重放战斗逻辑或随机数。系统突然杀进程前的异步保存不保证一定完成，因此正常自动保存仍保留；恢复精度以最后成功落盘为准。

## 存档

- Windows：现有 Electron 文件路径不变。浏览器：原 localStorage 槽位不变。
- Android：应用私有 DATA 目录下 `save_1.json` 至 `save_6.json`。每槽两个模式仍共存，存档版本仍为1。
- 写入同槽位时排队，先写临时文件再重命名，不同时覆盖两种模式。失败时显示提示，菜单退出等待保存成功。
- 首页、继续与管理统一通过存档模块读取；读取完成前禁止开始覆盖操作。
- 手机存档管理中先选择槽位，可导出 JSON，通过系统分享保存到用户选择位置。导入通过系统文件选择器，先验证内容与版本，再明确确认覆盖该槽位两个模式。
- 导入会将内部 saveSlot 更新为目标槽位；不兼容/损坏/空备份不覆盖原数据。
- 应用不申请公共存储权限，不提供云同步。电脑与手机存档不会自动互通。卸载、清除数据会删除私有存档，务必先手动备份。应用自动备份已禁用。

## 本地工具链

1. Node.js 22或更高，执行 `npm ci` 安装依赖。
2. 安装 Android Studio 与 JDK 21（可使用其兼容的内置 JDK）。
3. SDK Manager 中安装 Android SDK Platform 36、Build Tools 36.0.0、Platform Tools，并接受 SDK 许可。
4. 为当前终端配置 `JAVA_HOME` 指向 JDK 21，`ANDROID_HOME` 指向 Android SDK；也可让 Android Studio 创建被忽略的 `android/local.properties`，设置 `sdk.dir`。
5. 执行 `npm run android:doctor`。首次编译还需联网下载 Gradle、Google Maven 与 Maven Central 依赖；完成安装后的游戏本体离线运行。

构建命令：

```powershell
npm run android:doctor
npm run android:debug
```

测试包输出：`android/app/build/outputs/apk/debug/app-debug.apk`。

只同步资源：`npm run android:sync`。打开原生工程：`npm run android:open`。

调试包只供测试。不同电脑或临时 CI 的 debug 签名可能不同，不能保证互相覆盖安装；不要为安装新测试包直接卸载旧包而丢失存档，应先导出。

### Android 启动检查更新

每次冷启动自动检查 GitHub 仓库 `xiuyi-ctrl/CardGame` 最近100条 Release，首页左下角显示实际安装版本和检查状态。仅识别 `v主版本.次版本.修订号` 的正式发布，排除草稿、预发布及没有 APK 的版本；按数字比较版本，发现更新后点击入口在外部浏览器打开发布页。网络失败可手动重试，检查过程不阻止开始或继续游戏。

发布 Android 新版时，更新 `package.json` 版本号，用相同签名生成 APK，并把 APK 上传到该版本的 GitHub Release。现有 Windows 标签发布流程只上传 EXE，Android 测试工作流产物也不属于 Release；这两种情况都不会被识别为手机新版。覆盖安装须保持包名和签名一致，建议先备份存档。
