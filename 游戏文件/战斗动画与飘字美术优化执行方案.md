# 战斗动画与飘字美术优化执行方案

记录日期：2026-10-24。

本文将战斗表现优化方案整理为可分批执行的工作清单。2026-10-24已实施第一批与第二批，详见[第一批实施记录](战斗动画第一批实施记录.md)和[第二批实施记录](战斗动画第二批实施记录.md)；第三批仍为待执行设计。

## 一、目标与范围

让玩家直接看清“谁使用技能、命中谁、本次造成多少伤害、随后触发了什么”。同一次命中的实际耗盾与扣血合并显示伤害数字，护盾与生命仍各自按实际结果变化。沿用现有像素生物、底座和战斗布局，电脑与横屏手机共用表现规则。

- 优先改善飘字、基础攻击、命中、治疗和护盾，再补复杂技能与体系专属美术。
- 保持已经确认的逐段连击、同段群攻同步和战斗全灭停止规则。
- 动画读取战斗结果，不参与伤害、目标、随机数、冷却和次数计算。
- 不增加暴击、元素克制或新的战斗机制；强烈视觉反馈不代表额外伤害。
- 手机继续动态适配不同横屏尺寸，主要操作可达，不增加竖屏页面。
- 各批次分别交付、验证，不同时重写全部战斗表现。

## 二、当前实现与实施入口

以下为本方案制定时核对的现状，后续执行前应复查工作区。

| 入口 | 当前职责 | 本次可能调整 |
| --- | --- | --- |
| `src/game/core/battle.ts` | 战斗结算、日志与状态快照 | 仅在必要处补充实际结果的表现元数据 |
| `src/game/types.ts` | `LogEntry` 等数据类型 | 可选的表现字段，兼容旧日志 |
| `src/ui/battleFx.ts` | 日志解析、动画调度、飘字与快照回放 | 动作阶段、飘字类型、分段时序 |
| `src/ui/BattleScreen.tsx` | 战场、详情与操作区 | 显示独立特效层、必要的定位引用 |
| `src/ui/styles.css` | 桌面与共享战斗样式 | 像素文字、位移、闪光、碎盾等表现 |
| `src/ui/mobile.css` | 手机尺寸与布局 | 位移上限、飘字避让、特效密度 |
| `src/ui/pausableTimers.ts` | 表现层暂停与恢复 | 优先复用，不另建第二套计时器 |

当前动画主要通过日志文本解析生成事件，已有生命、状态、护盾快照及 `simultaneousGroup`。默认事件间隔为800毫秒，清理时间为1300毫秒；支持1倍、2倍、4倍速度及跳过动画。

相关已执行规则见[群体技能同步结算与动画](群体技能同步结算与动画.md)和[战斗全灭终止规则](战斗全灭终止规则.md)。其中旧文档“随机多目标分批”的表述，应结合后续修复理解：迅针、叶针、连击、火焰连击等连续随机技能逐次播放，不能因为命中了不同敌人就同时播放。

## 三、必须保留的播放规则

| 情况 | 动画顺序 |
| --- | --- |
| 单体单段攻击 | 起手 → 出手 → 命中与数字、生命／护盾变化 → 回位 |
| 连续随机攻击 | 第一次实际命中 → 第二次实际命中 → 后续命中；使用已有结算目标，不重新抽取 |
| 单目标连击 | 每一段独立显示命中与血量变化，不能合并为一个总伤害 |
| 单段群攻 | 一次施法；同段所有合法目标同时命中，分别显示实际结果 |
| 多段群攻 | 第一段全体同步 → 该段后续效果 → 第二段全体同步 |
| 双尾扫焰 | 保留当前两名不同目标同批命中的表现；只有一名目标时只显示一次 |
| 群体治疗／护盾／增益 | 一次施法，全体目标同步变化；后续净化等按已有结算顺序播放 |
| 反伤、烙印引爆、被动回复 | 跟随所属命中或触发事件，不抢在主效果前播放 |
| 灼烧／中毒等持续伤害 | 以独立状态伤害显示，不伪装成又一次攻击动作 |
| 一方全灭 | 保留终结命中、同批目标和必要死亡反馈，停止后续攻击／治疗／增益动画 |
| 车轮战仍有替补 | 保留死亡反馈与替补入场，不能提前按整场结束截断 |

伤害前剥盾、免疫、减伤等参与当前伤害计算的效果，仍在对应命中前或命中时体现。表现层不借优化顺序改变其实际生效时机。

## 四、第一批：基础反馈

### 1. 飘字分类与文案

| 类型 | 初版表现 | 文案与数值要求 |
| --- | --- | --- |
| 命中伤害 | 奶白数字、深色像素描边，短暂弹起后淡出 | 实际耗盾＋实际扣血，仅显示一个合计数字 |
| 明显重击 | 数字稍大，短暂放大一次 | 不添加“暴击”等不存在的判定 |
| 治疗 | 绿色数字，平缓上升 | `+5`，显示实际回复，不能把溢出治疗算进去 |
| 获得护盾 | 蓝色盾图标与数字，向外轻弹 | `盾 +4`，使用实际增加量 |
| 护盾受损 | 合并到本次伤害数字，保留格挡／破盾光效 | 不另显示蓝色耗盾数字；完全由护盾吸收时也显示统一伤害数字 |
| 灼烧／中毒伤害 | 对应状态图标与数字 | 伤害来源明确，沿用真实结算值 |
| 附加状态 | 非持续伤害状态可显示图标与短文字，位于伤害数字下方 | 灼烧、中毒附加时不播放状态动画或新增层数飘字；状态栏图标正常更新 |
| 免疫／无效 | 灰白色短提示 | 显示已有结算原因；不把未命中、免疫、满血混为一类 |

例如目标有5点护盾、5点生命，受到8点攻击，实际消耗5点护盾、扣除3点生命，只显示`−8`，不拆成两个数字。完全被护盾吸收时，同样显示实际消耗护盾对应的伤害数字。若无盾且实际仅扣1点生命、名义伤害为8，仍只显示`−1`，不计过量伤害。满血治疗不显示虚假的绿色回复数；可用小型“生命已满”提示说明施法结果。

附加灼烧、中毒等持续伤害状态采用静默更新，不播放额外施法／受击状态动画，也不显示“灼烧 +N／中毒 +N”飘字。攻击本身、其他同时发生的治疗／获盾效果及回合末持续伤害的实际扣血反馈不受影响。

明显重击的建议初始门槛为“单次实际耗盾与扣血合计至少6点”，仅改变表现，暂不以整次群攻或连击总和判断。该门槛与放大幅度属于可调表现参数。

### 2. 飘字布局与生命周期

- 同一目标的连续命中交替向左上、右上小幅偏移，让新数字保持可读。
- 伤害合计、获得护盾与状态标签分开排布；同次命中的耗盾与扣血不拆成两条飘字，相关信息共同出现。
- 群攻分别在各目标附近显示，不用一个总数代替所有目标。
- 飘字锚定生物上半身附近；避开底部生命／速度、状态栏和操作按钮。
- 靠近战场边缘时向内收，不能越出可见战场或被面板截断。
- 旧数字正常淡出，不能为显示新数字而把所有已有数字瞬间清空。
- 1倍速下数字建议显示700～1000毫秒；加速时同步缩短，确保相邻段仍可区分。
- 正文继续使用现有字体体系；优先复用已有数字字形，描边和位移保持像素感。

### 3. 攻击与命中

普通近战：轻微后撤／压低 → 朝实际目标方向短距离冲出 → 命中亮闪和数字 → 回位。只移动生物立绘，底座与卡位固定。

普通远程：短施法动作 → 独立弹道 → 目标命中。弹道与受击、数字、血条变化在同一命中时点衔接。首批只按当前已有技能明确划分近战／远程，不建立自动猜测规则。

| 结果 | 命中表现 |
| --- | --- |
| 生命受损 | 短暂亮闪、轻微后退，生命条同步下降 |
| 全部伤害由护盾吸收 | 盾面亮闪、少量碎屑，不播放明显的生命受伤动作 |
| 护盾从大于0降到0 | 一次破盾碎裂；不重复播放多次破盾 |
| 治疗 | 绿色光效向上掠过，不做受击抖动 |
| 增盾 | 蓝色轮廓展开，护盾数字同步增加 |
| 免疫或无效 | 与实际原因对应的小提示，避免完整重击反馈 |

普通攻击不震动整个屏幕。位移按当前立绘显示尺寸计算并设上限；不能挤到其他卡位、遮住单位数字或移动操作区。

### 4. 第一批交付

1. 补齐实际扣血、耗盾、加盾、治疗的表现数据。
2. 更新飘字组件与共享样式。
3. 接入基础攻击起手、命中和回位，先选单体近战、远程、治疗、护盾各一个技能验证。
4. 扩展到使用相同表现的技能。
5. 完成桌面、手机实际渲染验收和专项回归。

完成标准：无虚报伤害／治疗，同次命中的耗盾与扣血合并为一个实际伤害数字，护盾与生命各自变化正确，多段数字不完全重叠，手机按钮与数值始终可读。

## 五、第二批：复杂技能、被动与死亡

### 1. 连击与群体表现

- 迅针逐次发出弹道，分别飞向已结算的目标；不能重新计算随机目标。
- 同目标连击每段重新触发命中表现，防止CSS类名未变化导致只有第一段有动作。
- 群攻每段只播放一次施法动作，多个目标同时反馈，避免施法者同一时刻重复叠加位移。
- 全体治疗与护盾使用统一施法光效，各目标保留各自数值。
- 伤害后的被动、反击和状态引爆沿现有顺序衔接，保留生命、护盾与状态快照。

### 2. 被动与状态

- 被动触发不显示“小图标＋被动名”浮动提示，仅以实际伤害、治疗、获盾或状态变化说明结果；常驻被动栏、详情及战斗日志保留。
- 同一次被动产生的多个结果可在同一反馈时段内呈现；不同触发源不合并。
- 非持续伤害状态的图标在实际附加或新增层数时轻弹一次，动画期间不提前显示最终层数。灼烧、中毒继续静默更新，不播放附加动画或层数飘字。
- 多条被动按原触发顺序展示结果，不增加被动名称文字，不覆盖生物姓名、数值或技能操作。
- 反伤以攻击者为受伤目标表现，不再让受击者重复播放一次普通攻击动作。

### 3. 死亡与复活

- 死亡顺序为最后伤害反馈 → 短暂失色／下沉／像素消散 → 单位视觉离场。
- 保留终结群攻所有目标的反馈，不因第一个目标触发胜负而漏掉同批其他目标。
- 岩壳碎片等死亡连锁继续按现有战斗规则处理，不由特效自行生成伤害。
- 时砂回溯使用反向砂粒聚拢和重新亮起的表现，配合实际恢复生命数字。
- 替补入场与复活不是同一种动画；车轮战不得误显示胜负结算。
- 胜负弹窗等待必要终结反馈完成；跳过动画时立即进入正确的最终显示。

## 六、第三批：体系专属特效

| 体系 | 首批美术 | 约束 |
| --- | --- | --- |
| 灼烧 | 小火球／火羽弹道、焰刃命中、附着火星 | 火焰不遮住生命与状态层数 |
| 中毒 | 毒滴弹道、紧凑腐蚀光、附毒图案 | 与灼烧在颜色、形状上均能区分 |
| 护盾 | 蓝白盾面、格挡闪光、破盾碎片 | 与治疗绿光区分 |
| 狐火 | 复用专属图标配色的小型灵焰 | 狐火层数仍由UI绘制，不烘焙进图片 |
| 灼烧烙印 | 烙印收缩、紧凑火环引爆 | 在触发攻击后播放，不提前清空状态显示 |
| 火种 | 小火种跃出与熄灭 | 与普通灼烧、狐火保持不同轮廓 |
| 时砂 | 沙粒聚拢、简短回溯光环 | 仅在真实回溯事件触发 |

优先复用每个体系的弹道、命中和附加效果，不要求每个技能单独制作一整套动画。已有灼烧、狐火、烙印、火种及时滞图标作为配色与形状参考。

## 七、美术制作与资源接入

- 生物继续采用已确认的64×64像素立绘；新增特效以接近的像素颗粒制作，避免高细节光效与粗像素生物不协调。
- 每张特效只包含自身图案，透明背景，不包含生物、地面、卡框、伤害数字或技能文字。
- 命中特效建议从4帧2×2小图集开始；只有确实需要连续变化时再增加帧数。
- 弹道与命中特效分开制作，便于匹配不同目标距离和群攻落点。
- 原稿、透明导出、提示词、预览及检查记录保存到 `design/battle-fx/` 对应批次目录。
- 实际资源建议放在 `public/battle-fx/`，归档同步到 `美术素材/battle-fx/`；若复用项目已有同类目录，执行时统一沿用该目录。
- 层数与数字由代码显示，不生成带固定数值的图片。
- 对首批资源检查透明边缘、品红残留、裁切、锚点及各帧大小一致性。
- 接入后复查敌我方向、左右边缘、前后排叠放与手机缩小显示，不能只看原尺寸素材。

## 八、实现约束与时间参数

### 1. 逐步补充表现元数据

优先扩展现有日志到动画事件的路径。对仅凭日志文字和快照差值无法可靠区分的情况，增加可选表现字段；至少能明确技能来源、目标、实际扣血、实际耗盾、实际治疗和实际加盾。

- 实际变化在结算发生处记录，不能在动画层重新模拟伤害或读取最终血量倒推全部段数。
- 同批群攻日志共享快照，不能直接用相邻两条群攻日志的快照差来计算每名目标的数值。
- 反伤、护盾忽略、真实伤害、复活、溢出治疗和护盾上限分别核对。
- 保留旧日志解析回退；旧字段缺失时不产生伪造数值，也不拒绝原有存档。
- 不为本次表现优化新增独立战斗状态机或另一套技能配置表。

### 2. 建议初始时间

下表为1倍速初始调试值，不是已经实施或最终锁定的参数。

| 动作 | 初始范围 |
| --- | --- |
| 起手 | 60～100毫秒 |
| 普通出手／弹道 | 120～220毫秒 |
| 单次命中亮闪 | 60～100毫秒 |
| 回位 | 100～160毫秒 |
| 普通完整攻击节拍 | 450～650毫秒，包含命中后的短停留 |
| 连击后续命中间隔 | 180～260毫秒，首段完成起手后进入连续节奏 |
| 飘字保留 | 700～1000毫秒，可跨越后续连击段 |
| 普通死亡反馈 | 200～350毫秒 |

不能只把全局800毫秒替换成更小数字就视为完成。逐段命中与后续被动需要明确的时点，弹道落点、伤害数字、快照与状态变化必须对齐。

所有计时与CSS动画速度统一响应1倍／2倍／4倍。暂停、恢复、跳过、退出战斗和替换战斗状态时，清理过期回调、弹道、位移与飘字，避免新战斗收到旧动画。

## 九、手机动态适配与性能

- 覆盖横屏640×320、640×360、740×360、844×390、915×412、1024×600，以及运行中尺寸变化。
- 飘字字号与偏移设上下限；小屏优先减少粒子、缩短轨迹和压缩标签，不能靠整页缩放解决。
- 以战场中的实际单位显示位置定位特效，不假设固定窗口或固定像素坐标。
- 动画层不拦截原有点击、长按、右键、拖动和结束回合按钮。
- 主要操作保持至少44×44 CSS像素触控区域，不能被特效层覆盖。
- 每名目标保留必要数字与状态反馈；性能不足时先减少装饰碎屑，不漏掉整次命中。
- 优先使用现有React、CSS和本地图片资源，不为首批引入新的动画依赖。
- 特效按需预加载，退出战斗后及时清理；不能给每个单位永久挂载全部体系动画。

## 十、执行步骤与验收关卡

| 步骤 | 工作 | 完成后检查 |
| --- | --- | --- |
| 1 | 核对现有事件与快照，制作固定战斗案例 | 区分生命、护盾、治疗、持续伤害和被动来源 |
| 2 | 补充必要的可选表现元数据 | 与真实结算一致；旧存档可继续；不增加随机调用 |
| 3 | 实施第一批飘字与布局 | 数值准确、来源可辨、连击不重叠、手机不越界 |
| 4 | 实施第一批攻击、治疗与护盾动作 | 动作指向正确，命中时点与数值变化一致 |
| 5 | 实施第二批连击、群攻、被动与死亡 | 保留逐段／同段同步、终结截断及替补规则 |
| 6 | 制作并接入第三批体系美术 | 专属效果可辨，帧图透明无裁切，数量受控 |
