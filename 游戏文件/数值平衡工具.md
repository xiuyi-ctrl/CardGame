# 统一数值平衡工具

## 用途

平衡工具使用与游戏相同的 reducer、战斗引擎和可播种随机源批量运行主线及熟练度远征。它用于发现流程卡死、非确定性和明显数值漂移，不会自动修改技能、生物或经济数据。

战斗内的目标抽取、事件选项效果、失败惩罚和遗物赠送都由局种子派生；除“新建游戏”生成初始种子外，流程逻辑不得直接调用非播种随机数。`balance:check` 会对相同配置和种子复跑并比较终局签名。

自动玩家是一套固定策略，不等同于真人玩家：主线会轮换御三家与同伴组合，优先选择安全收益、主动购物和满足条件时融合；战斗时低血治疗、集中攻击可达的低血目标。熟练度模式覆盖 6 只初始宠物的确定性搭配，优先购买治疗与成长资源、强化主力攻击技能，其次提升生命和速度。报告适合比较提交前后的相对变化，不应把绝对胜率直接当作真人胜率。

## 命令

```bash
# 主线普通/困难/地狱 + 熟练度普通，各 100 个固定种子
npm run balance

# 每个配置 1000 个种子，用于较低噪声的深度分析
npm run balance:deep

# 生成报告、与基线比较，并执行硬门禁和确定性复跑
npm run balance:check

# 明确接受当前数值后更新 tools/balance/baseline.json
npm run balance:baseline
```

可追加以下参数：

| 参数 | 含义 |
| --- | --- |
| `--mode main\|proficiency\|all` | 选择模式 |
| `--difficulty normal\|hard\|nightmare\|all` | 选择难度；熟练度默认只跑普通，显式指定时可单独分析其他难度 |
| `--seeds N` | 每个模式/难度配置的种子数 |
| `--seed-start N` | 起始种子，默认 2000 |
| `--out PATH` | 报告目录，默认 `balance-output/latest` |
| `--check` | 开启确定性复跑和硬门禁 |

`balance-output/` 已加入 `.gitignore`。每次运行生成：

- `balance-report.json`：逐局结果、战斗摘要和全部聚合数据，适合程序分析。逐事件遥测只在内存中参与聚合，写盘前会清空，保证 1000 种子深度报告可序列化。
- `balance-report.md`：模式、节点、技能、生物、被动和告警摘要，适合人工检查。

报告记录 Git 提交、自动玩家版本、种子区间和配置。只有基线 JSON 受版本控制，普通报告不会进入仓库。

## 指标

- 全局：胜负、卡死/异常、到达幕次或层数、步骤数、单局耗时。
- 战斗：节点胜率、Boss 到达率与胜率、轮数 P50/P95、疲劳触发率、双方阵亡。
- 技能与被动：技能按模式、难度、玩家/敌方拆分，记录使用次数、解析目标数、实际生命伤害和治疗；被动记录触发次数。
- 生物：战斗登场、死亡和终局存活。
- 经济与成长：金币收支、商店访问、驯服、阵亡、融合、成长点获取/消费、技能强化和竞技场结果。

结构化战斗遥测仅在模拟器开启 `collectTelemetry` 时收集。正常游戏不创建这些字段，不增加正式存档体积；遥测也不调用 RNG，因此开启前后战斗结果和 `rngCount` 必须一致。

## 门禁与告警

以下情况使 `balance:check` 返回失败：

- 抛出异常或进入自动玩家不认识的界面。
- 连续 5 步状态无变化，或主线超过 2500 步、熟练度超过 6000 步仍未结束。
- 单位出现非有限数值，或同一单位集合出现重复 UID。
- 同一配置与种子复跑的最终签名不一致。

基线差异只告警、不使 CI 失败：胜率/Boss 指标变化超过 10 个百分点；轮数、经济、伤亡或成长指标变化超过 20%；样本量至少 30 时，技能、生物或被动指标变化超过 25%。这避免有限样本的正常波动阻断开发。

技能数值不按总伤害直接调整。只有同一阵营样本不少于 100 次，且至少两个配置中的单次收益持续高于或低于同类中位数 50%，才进入 ±1 点的单变量复核；范围和状态技能还必须结合目标数、有效回合与被动触发分析。

## 基线更新流程

1. 先运行 `npm run balance:check`，阅读 Markdown 报告并确认所有硬失败已解决。
2. 对照玩法目标审查胜率、Boss、轮数、经济和技能排行变化。
3. 确认变化是预期的新平衡后运行 `npm run balance:baseline`。
4. 将代码、测试、文档和 `tools/balance/baseline.json` 放在同一次提交中评审。

GitHub 的 `Quality` 工作流会在 `main` 推送和 Pull Request 上执行类型检查、全部测试及 `balance:check`，并始终上传本次平衡报告作为构建产物。
