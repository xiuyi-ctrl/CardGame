# 手机全界面动态适配验收清单

日期：2026-10-21。手机仅支持横屏游戏布局；Android 保持双方向横屏锁定，网页竖屏仅显示旋转提示，不提供继续竖屏入口。不修改玩法、数值、存档结构、关闭规则和电脑端布局。

## 布局规则

- 手机入口仍为 Android 或符合触控媒体条件的网页；手机 CSS 最后加载并限定在 `.mobile-ui` 下。
- 使用实际 CSS 视口和安全区，不按物理截图像素计算尺寸，不使用整页缩放。
- 覆盖桌面媒体查询遗留的最小高度、绝对定位及纵向堆叠；立绘、卡片网格与间距按可用空间调整。
- 常规操作页以一屏为先；图鉴、背包、地图、成就、测试长列表及完整详情允许必要滚动，触控按钮至少44×44 CSS像素，不通过整页缩放或裁切掩盖内容。
- 战斗菜单使用标题栏预留空间；技能双列排列，目标范围、关键数值、次数与冷却常驻，长按生物查看完整技能与条件，不显示详情按钮。
- 商店四件商品两列两行；效果说明可点击打开全文，购买按钮独立。招募保持两位候选，不添加技能描述、下一形态或融合信息。
- 八只伙伴优先使用紧凑网格。初始伙伴、队伍、布阵、进化与结算采用按需详情，关闭后不改变选中对象；Android 返回与 Escape 优先关闭详情。
- 成长点转移在手机端聚焦转移栏，来源、接收对象、数量、手续费和确认保持同屏；返回后恢复原成长对象。
- 熟练度远征开局选宠页（proficiency-select）按用户最新要求保留原有内容和布局，不纳入本次一屏精简。
- 普通融合确认仍只展示融合后的伙伴；熟练度营火融合保留原有主副宠与技能继承流程。

## 自动检查与实际渲染

新增8项全界面布局约束检查，连同原有4项开局检查共12项。这些只检查 CSS 约束与夹具覆盖，不冒充视觉验收。

独立 Electron 验收使用真实 Chromium 排版、隐藏窗口，不启动 agent-browser。夹具及私有页面导出只在验收服务器启用，不进入生产入口、Windows 包或 APK。

```powershell
# 全部页面／压力状态，六种横屏
.\node_modules\.bin\electron.cmd tools/mobile-layout/check.cjs

# 指定页面的小屏快速复查
.\node_modules\.bin\electron.cmd tools/mobile-layout/check.cjs --quick --scenes=shop,battle-selected,roster-long

# 不重新挂载组件，检查运行中横屏尺寸改变及选择保留
.\node_modules\.bin\electron.cmd tools/mobile-layout/check.cjs --quick --resize --scenes=starter,formation,battle-selected,shop,growth-transfer

# 关闭手机模式，复查桌面布局
.\node_modules\.bin\electron.cmd tools/mobile-layout/check.cjs --desktop --scenes=title,map,formation,battle,shop,roster,arena3,codex

# 小屏截图索引
.\node_modules\.bin\electron.cmd tools/mobile-layout/gallery.cjs
```

手机矩阵：640×320、640×360、740×360、844×390、915×412、1024×600，均为 CSS 像素。额外通过 `--resize` 在不重新挂载页面的情况下切换横屏尺寸，检查当前选择和页面可达性。

使用 Electron 的 Chromium 设备模拟明确指定 CSS 视口，避免 Windows DPI 和窗口外框影响测量。检查等待实际使用的字体与图片加载完成，不以窗口外框尺寸代替页面视口。

产物在被 Git 忽略的 `dump/mobile-layout/`：

- `index.html`：页面、视口、截图链接及自动几何检查结果。
- `report.json`：越界、父容器裁切、横向溢出、遮挡、小触点、滚动到底、常规页面一屏检查和运行中尺寸切换结果。
- `run.json`：本轮 CSS 的 SHA-256、用例数及失败列表。
- `desktop.html`／`desktop-report.json`：桌面复查结果。
- 页面 PNG 与 `gallery-*.png`：视觉核查证据。

发现错误时脚本返回非零退出码。已列入一屏清单的常规页面出现纵向滚动视为失败；地图、背包、图鉴、成就、测试长列表和完整详情保留必要滚动，不把所有数据强挤进首屏。快速检查会重写手机报告，完整交付以全矩阵结果为准；只有明确影响范围的局部修复可使用 `--merge` 保留未受影响的截图。

修改严格限定于单个页面时，可用 `--scenes=test-pick --merge` 专项复测七种尺寸并更新原报告，`run.json`分别记录新测与保留用例数量；共享样式变化必须重跑全矩阵，不能据局部复测声称全部页面通过。

## 仍需 Android 真机复核

### 自动提示入场闪高修复

首次高度修复没有覆盖桌面toast-in动画对top的临时覆盖：修复前在640×320下，0～299毫秒的提示高度为246～266px，320毫秒后才恢复36.8px。手机端现已移除这段入场动画，仅保留结束淡出；减少动画偏好下不播放动画。

验收夹具已移除关闭提示动画的内联样式，并强制启用动画媒体条件；重新启动真实CSS动画，采样0、16、80、150、299、320、2200、2350毫秒。全部80类页面／状态、七种手机视口共560个组合通过；其中21个提示组合共168个动画时间点高度无变化。相关测试20项通过，Android打包通过。修复前证据在dump/toast-flash-before-report.json，最终逐帧尺寸保存在dump/mobile-layout/report.json的toastFrames中。

### 友方技能目标标记复核

单体友方技能复用现有合法目标集合：可选伙伴显示绿色边角标记，不可选伙伴立绘变暗；取消选择后清除标记，非法目标不派发指令。电脑与手机使用相同规则，自身／全体技能继续直接施放。

新增治疗、炉壳两个目标选择状态后，共80类页面／状态，七种手机视口全量检查560个组合通过；最终标记层级调整仅影响这两个状态，另行复测14个组合并合并报告，保留546个不受影响的组合。电脑端两种尺寸8个组合通过；相关行为测试28项通过，类型检查和Android打包通过。渲染工具同时记录共享样式与手机样式摘要，并在战斗截图前等待画布立绘图片解码。

Chromium 验证不等于全部 Android 设备验收。请用最终 APK 覆盖安装，复核系统栏／刘海安全区、系统字体放大、旋转、触控滚动及原生导入／分享，尤其是不同厂商 WebView 的表现。不要先卸载旧包；签名不兼容时先导出存档。

手机适配阶段未修改正式签名；后续版本发布按用户明确要求执行。
