# 熟练度相关五类界面美术稿

使用 frontend-design 确定层级与布局，内置 image_gen 生成五张独立16:9预览，完整提示词保存在对应 .prompt.txt。五类已按组件接入运行时代码；没有启动浏览器或提交 Git。

## 共用规范

沿用营地系列：奶油底 #fff9e9、深墨阶梯框 #101c2c、灰绿内线 #8a979b、橙金 #ff8a08、青绿 #168d89；危险后果单独用暗红。像素标题，清晰正文；透明红心、闪电及黑色数值，不在技能名前放图标。伙伴完整落在独立留白区域，不扩大到遮挡文字。标题与操作区固定，仅内容滚动并隐藏滚动条。无圆角、模糊或持续动画。不得将整张预览用作运行时背景。

## 1. skill-replacement-v1.png：技能学习与替换

本张展示已选旧技能后的新技能选择：左侧目标伙伴、剩余成长点和待替换技能，右侧三张横向候选卡。点击即替换，不增加确认。非传奇替换保留8成长点刷新、最多3次以及资源不足禁用；传奇分支隐藏刷新。旧槽选择阶段使用同结构展示已有技能。技能学习复用前批 skill-learning-v1，不显示刷新，保留当前取消动作。所有技能描述、数值、强化、次数/冷却取实际数据；普通替换8点入场成本已在原动作扣除，不重复收取。

## 2. growth-transfer-v1.png：成长、成长点转移

左侧队伍、中间成长选项、右侧打开的转移面板；未打开时成长区使用空余宽度，不新增永久分屏限制。伙伴数量读取队伍，不固定3只。来源和目标不可相同；数量、手续费、到账分行，例转出10点，来源总扣10点、手续费5点、目标获5点，不再另扣5点。手续费采用 getTransferFee，50%向上取整。保留现有最终确认弹窗，不把稿中确认按钮改成直接转移；面板打开时成长操作与来源选择不应同时修改转移上下文。

成长生命每次+2、速度每次+1，消耗随 bonusStats 递增，不能采用主模式+5/+2。例中2点消耗仅为基础状态。技能槽顺序3/4/5，成本5/8/10，技能替换8；属性上限、负担能力及合法选项依据 getAllGrowthChoices/growthChoiceCost。商店效果待选时只选目标，不开放普通成长；普通返回地图、首领后继续前进、商店取消使用按原分支显示。

## 3. blacksmith-v1.png：铁匠铺、强化石、还原石

选宠态：共用左目录/右资料工作台，未选择时显示提示。选中后展示逐技能当前/强化后对比，消耗信息与动作分区。爪击+1例为7→9、消耗10点；叶针+2例为3伤害×4段且已满级，不提供继续强化；战吼例+2→+3效果值、消耗8点。具体效果、等级、满级上限及传奇倍率必须读取对应函数，而不是照抄预览。

强化石和还原石图示只出现在资源与操作处，复用已有独立素材，不替换成图中随机晶石。强化点/强化石/还原石保留各自确认弹窗，不提供批量强化；满级不显示强化动作，未强化不显示重置动作，缺少还原石时按现规则禁用。

背包强化石独立入口只显示道具强化相关动作，不凭空增加成长点强化入口；背包还原石入口只显示技能强化重置及预计返还。返回选宠和返回地图保留；调用原确认、扣除、返还动作，不在本次美术接入中顺带改动返还计算。

## 4. arena-three-modes-v1.png：竞技场三模式选择

三张横向整卡按钮：镜像模拟战/精英挑战赛/表演赛，插画是类别徽记，不作为真实敌方阵容预告。模拟战无伤亡无回血，胜利全体存活生物+5成长点，失败无惩罚；挑战赛对战3精英，胜利50金币与全体+3成长点，失败直接结束远征并保留死亡规则。表演赛花20金币，选择一只伙伴+5成长点，不是另一场战斗。金币不足20时表演赛禁用。整卡点击按原流程，不增加确认或退出入口。

## 5. proficiency-result-v1.png：熟练度远征结算

本稿胜利态，黎明营地、奖杯、两项统计、最终存活队伍和最高剩余成长点。到达层数=currentRow+1，总层数50；总战斗=获胜+失败场次；最高伙伴按当前存活队伍 growthPoints 排序，不把剩余点写成累计获得或历史最高。例中50层/41场/18、12、6点均为排版示意，来自实际状态后才能展示。

失败态复用报告结构但改为暮色/暗红与失败徽记；没有存活伙伴时显示空态，不伪造最佳伙伴。胜利才有重新开始，失败只保留原返回主菜单；不添加S级、评分、奖励领取、额外解锁或通用统计字段。

## 视觉检查与边界

已查看生成结果：五张主标题、操作文字与风险提示可读，伙伴未被面板裁切。成长转移稿出现较圆的滑条和个别按钮，接入时应按本系列改硬边像素控件；图中装饰徽记、植物底饰、示例立绘及数字不直接替换现有素材或数据。竞技场挑战插画仅为类别装饰，不新增物种或固定遭遇。

五张为类别主稿，不意味着强化石/还原石/失败态已各自生成独立全屏图片；其变化规则已在上文定义。后续实现保持业务状态与公共接口不变。
